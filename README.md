# Douga

ブラウザで再生中の動画を検出してダウンロードする **Chrome 拡張機能** と、URL を入力してダウンロードする **Windows デスクトップアプリ**。両者は localhost 経由で連携します。

```
┌────────────────────┐   POST /capture    ┌──────────────────────┐
│  Chrome 拡張 (MV3) │ ─────────────────▶ │  Douga デスクトップ  │
│  ページ上の動画を  │  127.0.0.1:47615   │  yt-dlp + ffmpeg で  │
│  検出・一覧表示    │ ◀───────────────── │  解析 / 変換 / 保存  │
└────────────────────┘   画質リスト・進捗 └──────────────────────┘
```

## できること

- 開いているページで再生中／読み込まれた動画の検出（`<video>`、HLS `.m3u8`、DASH `.mpd`、直リンク `.mp4` など）
- 検出した動画をワンクリックでデスクトップアプリに送信
- URL を貼るだけの単体ダウンロード（拡張なしでも使える）
- 画質を選んで保存。既定で HDR・高フレームレート・高効率コーデックを優先し、無劣化で保存
- 音声のみ抽出（既定は再エンコードなしで元の音質のまま）
- HLS/DASH のセグメント並列ダウンロードと mp4 への結合
- ログインが必要なサイト向けの Cookie 引き継ぎ（拡張側でオプトイン）
- ダウンロードキュー、同時実行数制御、進捗・速度・残り時間表示
- キューはアプリを閉じても残る。前回実行中だったものは「中断」として一覧に残り、ボタン一つでまとめて再開できる
- プレイリストの一括追加

## 対応サイトの考え方

**対応サイトの一覧は持ちません。** サイトごとの分岐を書くと、書いていないサイトで動かなくなるためです。代わりに、どのサイトでも同じ経路をたどります。

拡張機能から動画を送ると、アプリは次の順に**自動で**試し、最初に成功したものを使います。

1. **ページ URL をそのまま解析** — yt-dlp が対応している多数のサイトはここで完了します
2. **検出された HLS / DASH マニフェスト** — yt-dlp が知らないサイトはここで拾えます。画質を選べます
3. **検出された動画ファイルの直リンク** — 大きいものから順に
4. **ノイズとして降格した URL** — 他に何も無かった場合の最後の手段

1 が失敗しても、2 以降へ黙って切り替わります。切り替わった場合は「どの URL を使ったか」がアプリに表示され、すべて失敗した場合は「何をどう試したか」が一覧で出ます。

そのため、専用の対応が入っているサイトかどうかを気にする必要はありません。**動画を再生してから拡張アイコンを押す**、それだけです。

### サイト固有の処理は最小限

`extension/site-hints.js` に入っているのは、汎用処理では原理的に解決できない2件だけです。

- **再生リスト付きの URL** — リスト全体ではなく、開いている1本を対象にする
- **タイムライン上で再生するサイト** — ページ URL が `/home` のままで動画を指さないため、再生中の要素から投稿の個別 URL をたどる

これ以外は、トラッキング用クエリの除去のようにどのサイトにも効く処理か、広告・計測ドメインを一覧の下へ沈める処理だけです。降格であって除外ではないので、必要なら選べます。

## 画質について

既定で最高画質を取りに行きます。設定タブで変えられます。

**画質の優先度**

- **画質優先**（既定）— 解像度 → フレームレート → HDR（Dolby Vision 含む）→ 映像コーデック → 音声チャンネル数 → 音声コーデック → ビットレート の順で選びます
- **互換性優先** — H.264 + AAC を選ばせます。古い再生環境やスマホへの転送向け。画質は落ちることがあります

**解像度の上限** — 制限なし（既定）／4K／1440p／1080p／720p。上限内で最良のものが選ばれます。

**出力コンテナ** — 既定は「mp4（収まらなければ mkv）」。AV1 や Opus のように mp4 に収まらないコーデックのときだけ mkv になり、**再エンコードは発生しません**。「常に mp4」を選ぶと、収まらない組み合わせで再エンコードが起きて画質が落ちることがあります。

**音声のみ** — 既定は「元の音質のまま（再エンコードなし）」。mp3 などを選ぶと再エンコードされ、そのぶん劣化します。

最高画質は多くのサイトで**映像単体トラック**としてのみ配信され、映像と音声が1本にまとまったファイルは低画質であることが多いため、映像単体＋音声単体を取得して ffmpeg で結合します（`bv*+ba`）。ffmpeg が未インストールだとこの結合ができず、低画質の単一ファイルに落ちます。

## 高画質化（ダウンロード後の処理）

**元動画に無い情報は復元できません。** ここでできるのは 2 種類です。

**1. 劣化の除去（ffmpeg のみ・追加インストール不要）**

配信時の圧縮で入ったブロックノイズ・バンディング（グラデーションの縞）・リンギングを取り除きます。元動画に含まれる「傷」を消す作業なので、素直に見た目が良くなります。設定タブで選べます。

| プリセット | 内容 |
| --- | --- |
| 圧縮ノイズ除去（等倍） | `hqdn3d` + `deblock` + `gradfun`。解像度は変えず、圧縮の傷だけ取る |
| 軽い先鋭化（等倍） | 軽いノイズ除去 + `unsharp` |
| 2 倍アップスケール | ノイズ除去 → Lanczos で 2 倍 → 軽く先鋭化 |
| アニメ向け | バンディング除去を強めた 2 倍。平坦部が広いアニメ向けの調整 |

拡大は Lanczos で行いますが、これは**存在するピクセルを綺麗に補間するだけ**で、新しいディテールは生まれません。輪郭がぼやけにくくなる、という効果です。

**2. ディテールの生成（Real-ESRGAN・任意インストール）**

学習済みモデルが「ここにはこういう質感があったはず」と推測して描き足します。情報の復元ではなく生成ですが、見た目の解像感は確実に上がります。特にアニメで効果が大きく、実写では不自然になることがあります。

全フレームを一時的に画像として書き出すため、**1080p 5 分程度で 20〜40GB の空き容量**と Vulkan 対応 GPU が必要です。実行ファイルのパスを設定タブで指定してください。

**共通の注意**

- どちらも再エンコードを伴うため、厳密には「無劣化」ではありません。既定の CRF 18 は知覚上ほぼ劣化しない設定です
- 音声は再エンコードせずそのままコピーします
- 元ファイルは消さず、`〜 [enhanced].mp4` / `〜 [upscaled].mp4` として別名で書き出します
- 動画の長さによっては数十分〜数時間かかります。既定は無効です

なお、**まず元動画を最高画質で取ることのほうが効きます**。後処理で取り戻せる量より、720p ではなく 1080p を取るほうが差が大きいので、上の「画質について」を先に確認してください。

### うまくいかないとき

1. ログインしないと見られない動画なら、拡張機能の **Cookie を一緒に送る** を有効にする（既定はオフ）
2. `yt-dlp` を最新版に更新する（設定タブの「自動インストール」で入れ替わります）。サイト側の仕様変更は yt-dlp 本体の更新で直ることがほとんどです
3. それでも直らない場合、設定タブの **追加の yt-dlp オプション** に回避オプションを入れる。アプリを更新せずに対処できます

## できないこと

- **DRM 保護された動画（Widevine / PlayReady / FairPlay）は対象外です。** 主要なサブスクリプション配信サービスがこれに当たります。技術的保護手段の回避は日本の著作権法でも米国 DMCA でも違法とされるため、回避機能を実装する予定はありません。DRM ページを送った場合は「再生できる形式が見つかりませんでした」として次の候補へ進み、それも無ければエラーになります。
- 利用は各サイトの利用規約と、お住まいの地域の著作権法の範囲内で行ってください。日本国内では、権利者に無断でアップロードされた動画と知りながらダウンロードする行為は違法となる場合があります。自己責任でご利用ください。

## セットアップ

### 1. デスクトップアプリ

**`Douga起動.bat` をダブルクリックするだけです。** 初回だけ依存パッケージの取得が走るので数分かかります。Node.js が入っていない場合はその旨を表示します。

コマンドから起動する場合:

```bash
cd app
npm install
npm start
```

初回起動時、アプリが `yt-dlp` と `ffmpeg` を検出します。見つからない場合は「設定」タブの **自動インストール** ボタンで取得できます（Windows）。任意のパスを手動指定することも可能です。

**スタートメニューに登録したい場合**は、インストーラをビルドします。

```bash
cd app
npm run dist
```

`app/dist/` に生成されるインストーラを実行すると、通常の Windows アプリとしてスタートメニューとデスクトップにアイコンが並び、コマンドプロンプトの黒い画面も出なくなります。

アイコンを作り直す場合は `npm run icons`（`tools/generate-icons.js`）を実行してください。拡張機能用の PNG とアプリ用の `.ico` を、画像ライブラリなしで生成します。

### 2. Chrome 拡張機能

1. Chrome で `chrome://extensions` を開く
2. 右上の **デベロッパーモード** を ON
3. **パッケージ化されていない拡張機能を読み込む** で `extension/` フォルダを選択
4. デスクトップアプリを起動した状態で拡張のポップアップを開き、**アプリと接続** をクリック
5. アプリ側に許可ダイアログが出るので **許可** を押す（ペアリング完了、以降は自動接続）

## 使い方

**ページ上の動画を保存する**

動画のあるページで拡張アイコンをクリック → 検出された動画が一覧表示 → 「アプリに送る」。アプリ側で画質を選んでダウンロード。

ページ全体を yt-dlp に解析させたい場合（YouTube など、個別ストリームより確実）は「このページをアプリで開く」を使います。

**URL から保存する**

アプリの入力欄に URL を貼って「解析」→ 画質を選んで「ダウンロード」。

## 仕組み

### 拡張機能側

- `chrome.webRequest` でタブごとのネットワークを監視し、動画/マニフェストらしい URL を収集
- content script が `<video>` / `<source>` の `src`・`currentSrc` を走査し、`MutationObserver` で追跡
- `blob:` URL（MediaSource 経由）は直接ダウンロードできないため、元になったマニフェスト URL を候補として提示
- 送信時に `Referer` / `User-Agent`、必要なら Cookie を同梱（アプリ側で yt-dlp に渡す）
- `Content-Type` や拡張子があてにならないサイトでも拾えるよう、Chrome が `<video>` / `<audio>` のリクエストに付ける `type: 'media'` を主要な判定材料にしている
- `net-hook.js` がページ側の `fetch` / `XMLHttpRequest` を観測し、JSON レスポンスに含まれる動画 URL を拾う。MV3 の `webRequest` はレスポンス本文を読めないため、配信情報を先に API から受け取る作りのサイトでは、これが無いと再生を始めるまで候補が出ない。ページの動作を壊さないよう、本文はクローンして読み、例外は全て握りつぶして常に元の結果をそのまま返す
- `site-hints.js` は URL の整形とノイズの降格のみを担当。「このサイトは対応/非対応」という判定は持たない（対応可否はアプリが実際に試して決める）

### アプリ側

- `bridge.js` が `127.0.0.1:47615` で待ち受け。`chrome-extension://` 由来のリクエストのみペアリングを受け付け、以降はトークン必須
- `engine.js` が yt-dlp をラップ。`-J` でフォーマット一覧を取得、`--progress-template` で進捗をパース
- `engine.probeChain()` が上記のフォールバックを担う。「解析は通ったが形式が0件」も失敗とみなして次の候補へ進む
- `queue.js` が同時実行数を制御しながらジョブを実行。ジョブは `jobs.json` に書き出され、再起動後も一覧が残る。ただし起動と同時にダウンロードが走り出すのは驚きが大きいので自動再開はせず、「中断」として並べて明示的な操作を待つ
- 後処理の失敗はダウンロードの失敗と区別する。動画は保存済みなので、警告として出したうえで元ファイルへ辿れるようにする

## テスト

```bash
cd app
npm test
```

Electron を起動せずに Node だけで動きます。yt-dlp はスタブ（`test/fixtures/`）に差し替えるため、外部ネットワークもバイナリも不要です。

| スイート | 内容 |
| --- | --- |
| `engine` | フォーマット解析、`-f` セレクタの組み立て、進捗パース、Cookie の Netscape 変換 |
| `quality` | `-S` の優先順位、解像度上限、コンテナのフォールバック、音声の非再エンコード、形式一覧の並び |
| `title` | URL 由来のタイトルの判定、ページ側メタ情報での補完、出力ファイル名への反映 |
| `postprocess` | フィルタチェーンの組み立て、ffmpeg 引数、出力ファイル名、進捗パース |
| `site-hints` | URL 正規化、タイムライン再生時の対象特定、ノイズ判定、解析順の決定 |
| `fallback` | 未対応サイト・DRM ページ・ログイン要求のそれぞれで、正しく次の候補へ切り替わるか |
| `manifest-order` | 複数のマニフェストがあるとき、画質を選べる master を variant より先に試すか |
| `bridge` | ペアリング認可、トークン検証、CORS、Cookie の受け渡し |
| `queue` | 同時実行数、キャンセル、再試行 |
| `persistence` | ジョブの保存と復元、中断扱いへの変換、まとめて再開、履歴の上限、壊れたファイルの扱い |

拡張機能の `site-hints.js` は DOM に依存しないため、同じランナーから検証しています。
