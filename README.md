# Douga

ブラウザで再生中の動画を検出してダウンロードする **Chrome 拡張機能** と、URL を入力してダウンロードする **Windows デスクトップアプリ**。両者は localhost 経由で連携します。

```
┌────────────────────┐   POST /capture    ┌──────────────────────┐
│  Chrome 拡張 (MV3) │ ─────────────────▶ │  Douga デスクトップ  │
│  ページ上の動画を  │  127.0.0.1:47615   │  yt-dlp + ffmpeg で  │
│  検出・一覧表示    │ ◀───────────────── │  解析 / 変換 / 保存  │
└────────────────────┘   画質リスト・進捗 └──────────────────────┘
```

## できること

- 開いているページで再生中／読み込まれた動画の検出（`<video>`、HLS `.m3u8`、DASH `.mpd`、直リンク `.mp4` など）
- 検出した動画をワンクリックでデスクトップアプリに送信
- URL を貼るだけの単体ダウンロード（拡張なしでも使える）
- 画質を選んで保存、音声のみ抽出（mp3 / m4a）
- HLS/DASH のセグメント並列ダウンロードと mp4 への結合
- ログインが必要なサイト向けの Cookie 引き継ぎ（拡張側でオプトイン）
- ダウンロードキュー、同時実行数制御、進捗・速度・残り時間表示

## サイト別の使い方

| サイト | 推奨の手順 | 備考 |
| --- | --- | --- |
| YouTube | 「このページをアプリで開く」 | 再生リスト内の動画でも、開いている1本だけを対象にします。年齢制限つきは Cookie の送信が必要 |
| X (Twitter) | 「このページをアプリで開く」 | タイムライン上で再生している場合、ページ URL は投稿を指していません。拡張機能が再生中の投稿の個別 URL を自動で拾います。センシティブな投稿・鍵アカウントは Cookie が必要 |
| Pornhub | 「このページをアプリで開く」 | 年齢確認や会員限定の動画は Cookie の送信が必要 |
| Xvideos | 「このページをアプリで開く」 | 同上 |
| hanime.tv | 一覧から **HLS**（`.m3u8`）を選ぶ | yt-dlp の専用エクストラクタが無いため、拡張機能が検出したプレイリストを使います。会員限定の画質は Cookie が必要 |

いずれも、ログインしないと見られない動画を取る場合は拡張機能の **Cookie を一緒に送る** を有効にしてください（既定はオフ）。

サイト側の仕様変更で取得できなくなったときは、まず `yt-dlp` を最新版に更新してください（設定タブの「自動インストール」で最新版に入れ替わります）。それでも直らない場合は、設定タブの **追加の yt-dlp オプション** に回避オプションを入れることで、アプリを更新せずに対処できます。

## できないこと

- **DRM 保護された動画（Widevine / PlayReady / FairPlay）は対象外です。** Netflix、Amazon Prime Video、Disney+ などの保護コンテンツは扱えませんし、その回避機能を実装する予定もありません。
- 利用は各サイトの利用規約と、お住まいの地域の著作権法の範囲内で行ってください。日本国内では、権利者に無断でアップロードされた動画と知りながらダウンロードする行為は違法となる場合があります。自己責任でご利用ください。

## セットアップ

### 1. デスクトップアプリ

```bash
cd app
npm install
npm start
```

初回起動時、アプリが `yt-dlp` と `ffmpeg` を検出します。見つからない場合は「設定」タブの **自動インストール** ボタンで `app/bin/` に取得できます（Windows）。任意のパスを手動指定することも可能です。

Windows 用インストーラのビルド:

```bash
cd app
npm run dist
```

`app/dist/` にインストーラが生成されます。

### 2. Chrome 拡張機能

1. Chrome で `chrome://extensions` を開く
2. 右上の **デベロッパーモード** を ON
3. **パッケージ化されていない拡張機能を読み込む** で `extension/` フォルダを選択
4. デスクトップアプリを起動した状態で拡張のポップアップを開き、**アプリと接続** をクリック
5. アプリ側に許可ダイアログが出るので **許可** を押す（ペアリング完了、以降は自動接続）

## 使い方

**ページ上の動画を保存する**

動画のあるページで拡張アイコンをクリック → 検出された動画が一覧表示 → 「アプリに送る」。アプリ側で画質を選んでダウンロード。

ページ全体を yt-dlp に解析させたい場合（YouTube など、個別ストリームより確実）は「このページをアプリで開く」を使います。

**URL から保存する**

アプリの入力欄に URL を貼って「解析」→ 画質を選んで「ダウンロード」。

## 仕組み

### 拡張機能側

- `chrome.webRequest` でタブごとのネットワークを監視し、動画/マニフェストらしい URL を収集
- content script が `<video>` / `<source>` の `src`・`currentSrc` を走査し、`MutationObserver` で追跡
- `blob:` URL（MediaSource 経由）は直接ダウンロードできないため、元になったマニフェスト URL を候補として提示
- 送信時に `Referer` / `User-Agent`、必要なら Cookie を同梱（アプリ側で yt-dlp に渡す）
- `site-hints.js` がサイトごとの癖を吸収する。ページ URL の正規化（YouTube の再生リスト除去、X の投稿 URL への丸め）、タイムライン再生時の投稿 URL の特定、短命な実体 URL や広告配信ドメインの降格

### アプリ側

- `bridge.js` が `127.0.0.1:47615` で待ち受け。`chrome-extension://` 由来のリクエストのみペアリングを受け付け、以降はトークン必須
- `engine.js` が yt-dlp をラップ。`-J` でフォーマット一覧を取得、`--progress-template` で進捗をパース
- `queue.js` が同時実行数を制御しながらジョブを実行

## テスト

```bash
cd app
npm test
```

Electron を起動せずに Node だけで、エンジン（yt-dlp のフォーマット解析・`-f` 組み立て・進捗パース・Cookie 変換・追加オプションの分解）、サイト別処理（URL 正規化・X の投稿 URL 特定・候補の降格）、ブリッジ（ペアリング認可・トークン検証・CORS）、キュー（同時実行数・キャンセル・再試行）を検証します。yt-dlp はスタブ（`test/fixtures/`）に差し替えて実行するため、外部ネットワークもバイナリも不要です。

拡張機能の `site-hints.js` は DOM に依存しないため、同じランナーから `app/test/site-hints.test.js` で検証しています。
